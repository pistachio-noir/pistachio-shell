# Pistachio Noir Shell

A Quickshell (QML) desktop shell for Hyprland on a single-monitor desktop PC (Arch), in the Pistachio Noir colour scheme. All eight build phases (skeleton, bar content, Compositor adapter, quick settings, notifications, launcher, OSD/power menu/lock screen, motion polish) are done, and the bar auto-hides: the config lives in `src/`, linked to `~/.config/quickshell/pistachio`. The design is done and the plan is written; this repo is where the code gets built.

Read these first:

- `README.md`: requirements, installation, IPC commands and Hyprland keybinds, for the owner. Keep it in step when commands or requirements change.
- `docs/plan.md`: architecture, folder layout, theme tokens, components, build phases, risks.
- `docs/audio-bluetooth.md`: PipeWire, BlueZ, brightness and OSD design, with property names checked against the Quickshell 0.3.2 docs.
- `design/*.dc.html`: one HTML board per screen. Open `design/index.html` in a browser. These are the visual source of truth for sizes, radii, spacing and colours.

## Decisions (already made, do not reopen)

- Toolkit: Quickshell 0.3.2 with QML. A from-scratch shell in C++ or Rust is a separate, later project.
- Compositor: Hyprland only. mangowm is dropped for now. Keep a thin `Compositor` singleton so UI files never import a compositor module directly.
- Single monitor. Desktop PC: no battery, no UPower, no `Power.qml`. Wired network (Ethernet), no Wi-Fi.
- Bar: floating, centred pill at the bottom, 640 x 56, radius 28, 16 px above the bottom edge. It auto-hides when a window overlaps it (exclusive zone 0, thin bottom-edge strip reveals it on hover). No Hyprland bottom gap: tiled windows overlap the bar too, so it stays hidden while the workspace has windows (owner's call).
- Hyprland config: `~/.config/hypr/hyprland.lua` is Hyprland's stock default on a test install. The owner writes their own after a reinstall, so never edit it or tune the shell to it.
- Bar content: workspaces and window title, clock, date and notification indicator, status chip with Ethernet, Bluetooth and volume. Tray icons go in a second pill right of the bar, shown only while some app has one (owner's request, after phase 8). What's playing goes in a pill left of the bar, with its own media card on a click (owner's call, 28 October 2026). The bar stays centred by itself; the pills around it are not re-centred (owner's call).
- Other parts: quick settings (Ethernet, Bluetooth, Do not disturb, Night light tiles; volume, brightness and night light warmth sliders; uptime and power button), notification popups and centre, OSD, power menu, lock screen, app launcher, a polkit password dialog (owner's request, after phase 8; boards `design/polkit-*.html`), and a month calendar beside the notification centre (owner's request, after phase 8; board `design/calendar-notifications.html`; dates only, weeks from Monday).
- Launcher modes: Apps, Windows, Workspaces, System (volume, brightness, outputs), Bluetooth. It replaces Vicinae: it does everything the owner used Vicinae for (owner's call, 27 October 2026).
- Alt+Tab window switcher, from the owner's boards `design/window-switcher*.html` (after phase 8).
- The shell draws the wallpaper itself; hyprpaper retires (owner's call, 28 October 2026). Wallpaper switcher from the owner's boards `design/wallpaper-switcher*.html`, opened from the launcher, with a live preview; images in `~/Pictures/Wallpapers`, no slideshow.
- No overview (zoomed-out workspaces) in the shell: the owner uses a Hyprland plugin for that if needed. Window capture of every workspace works (checked), should this ever come back.
- Launcher keys: the arrows, plus Ctrl+H J K L as vim motions (owner's request, after phase 8). Keep both working, and keep plain letters typing into the search.
- Frosted panels (owner's call, 31 October 2026): a Shell setting, off by default, with Subtle (88 % opaque) and Glassy (72 %) styles, for the bar, its pills and the panels; their drop shadows go while it's on, and modal windows stay solid. The blur is Hyprland's, from a layer rule matching the namespaces `pistachio-bar` and `pistachio-panel` (README gives it). At the owner's explicit request Claude appended it to `~/.config/hypr/lua/rules.lua` on 31 October (backup `rules.lua.bak` beside it); the rule against editing the Hyprland config otherwise stands, and the owner carries the line into their own config after the reinstall. Panel backgrounds use `Theme.surface`, never a see-through colour of their own.
- Hyprland animations (owner's request and permission, 9 November 2026): Claude rewrote `~/.config/hypr/lua/animations.lua` in the shell's motion (one ease-out curve "pistachio", soft fades, windows pop in from 92 % without bouncing, workspaces "slidefade 12%"; the defaults are in `animations.lua.bak`) and added a `pistachio-motion` layer rule (`no_anim` for `^pistachio-`) to `rules.lua` (before it: `rules.lua.bak2`), so Hyprland doesn't fade the shell's layers on top of their own animation. Hyprland has no animation for its group tab bar. The owner carries these into their own config after the reinstall; otherwise the rule against editing the Hyprland config stands.
- LocalSend (owner's request, 2 November 2026; boards `design/*localsend*.html`): the shell is a LocalSend device itself (`services/localsend.py`, the protocol in Python's standard library), in quick settings, and all of it exists only while the LocalSend app is installed; the app must not run meanwhile (both need port 53317). Receive is off until switched on, the name is the hostname, a request shows during Do not disturb without a sound, a text shows in the toast with Copy and Close, and settings live in a Bluetooth-style card (owner's answers).
- Motion: smooth fades and slides, one easing curve (ease-out), 120 ms for hover and about 200 ms for fades and slides. Windows open and close through `components/Reveal.qml`: set the window's `open`, never its `visible`, so it stays up until its fade-out ends.

## Style rules

- Colours come only from `Theme.qml`. No hard-coded hex values elsewhere.
- Palette: bg #15170F, bgAlt #1D2016, overlay #2A2F1F, overlay2 #39412A, muted #626F51, subtext #A3B08F, text #E5E9D8, textBright #F6F8EF, pistachio #9FD88A (active state only), terracotta #DB8267, gold #E0B15E, sageBlue #7DA3B3, teal #7FC9A8, lavender #AC8ED0, clay #D9975A.
- `muted` is only about 3.4:1 on bg, so never use it for small text; use `subtext`.
- Pistachio marks what is active: current workspace, toggles that are on, slider fills, the cursor, and the selected-row chip (pistachio background with bg-coloured text). No accent borders and no large pistachio fills.
- Fonts: Manrope (weights 500 to 800) for the UI, JetBrains Mono for code-like text. Numbers use tabular figures.
- Shapes are soft: radius 28 for panels, 20 for chips and tiles, fully round for icon buttons.
- Panels and popups have the boards' drop shadows (`components/Shadow.qml`, sizes in `Theme.qml`), which the launcher's Shell settings can switch off; the bar and the tray pill stay flat. A window with a shadow needs room around its panel for it, masked so clicks pass through (see "Theme and motion" in `docs/plan.md`).

## Working rules for Claude Code

1. Verify any Quickshell module, type or property against https://quickshell.org/docs/v0.3.2/ before using it. Module and type names in `docs/plan.md` were checked in phase 1 (`SystemClock` and `DesktopEntries` are in `Quickshell`, `IpcHandler` in `Quickshell.Io`); check their properties when you first use them. `docs/audio-bluetooth.md` records how its open questions were settled (pairing agent, per-app volume filter, brightness IPC).
2. Follow the build phases in `docs/plan.md` in order, one at a time. After each, run the shell and check it against the matching board in `design/`.
3. Quickshell reloads on save. Run it with `qs -c pistachio` and read its log for QML errors before saying something works. The owner may already be running it (`qs -p src` or `qs -c pistachio`): check with `pgrep -ax qs` (the process is `qs`, not `quickshell`), because a second copy means two bars and only one can own the notification bus name. Reach an instance started with `-p src` via `qs -p src ipc call …` (`-c pistachio` looks up the symlinked path and misses it). `bin/psc` (linked as `~/.local/bin/psc`) wraps `qs -c pistachio`: `psc restart`, `psc <target> <function>`; `install.sh` links `src/` and `psc` into place; keep both and the README in step. Live reload only notices real writes: `touch`, `sed -i` (which replaces the file) and rewriting a file with the same content do not trigger it, so edit files in place. Even a real edit is sometimes missed: after each save, check that the log's count of "Configuration Loaded" lines went up (`qs log -c pistachio | grep -c "Configuration Loaded"`), especially when removing temporary test code. One cause, found 28 October: a file replaced by a new one (as Claude Code's Edit tool may save) loses its watch, so later writes to it, even in place, go unnoticed until a change to another file reloads the shell; write files in place (e.g. Python's `open(p, "w")`) and, after a missed reload, write another QML file in place to get it going. An edit to a `.js` file alone (the launcher's `fuzzy.js`) didn't reload at all, twice in a row; edit a QML file that imports it as well.
4. Keep services (`Apps`, `Audio`, `Bluetooth`, `Clipboard`, `Network`, `Brightness`, `Media`, `NightLight`, `Notifs`, `Polkit`, `Session`, `ShellSettings`, `Showoff`, `Store`, `ScreenShare`, `Files`, `About`, `Cider`, `Desktop`, `Drives`, `Library`, `LocalSend`, `Processes`, `Screenshots`, `Tldr`, `SystemStats`, `Tray`, `Uptime`, `Wallpapers`, `Weather`) and the `Compositor` adapter as the only places that touch system data. UI files only read from them.
5. Only one notification daemon can run at a time. Stop any existing one before testing notifications. On this test machine a KDE Plasma session may still be running on tty1; its `plasmashell` owns `org.freedesktop.Notifications` for both sessions (they share the user bus). Ask before stopping it (`systemctl --user stop plasma-plasmashell.service`; `start` brings it back).
6. Keep the existing screen locker bound as a fallback until the shell's lock screen is proven (the test machine has none, so the TTY is it). Keep a TTY available when testing the lock. If the shell dies while locked, run `hyprctl --instance 0 eval 'hl.clear_crashed_lockscreen()'` from the TTY. A live reload keeps the screen locked: singletons don't survive it, so `lock/Lock.qml` carries the lock state over with `PersistentProperties` (which doesn't work inside a singleton). Three wrong passwords lock the account for 10 min (pam_faillock), the TTY included.
7. The mockup sample content (window titles, device names, "1 Gbps", "3 h 12 min", "Until 07:00") is made up. Wire real data; do not copy the strings.
8. Night light uses `hyprsunset`, which the shell runs itself (CLI and IPC checked against the Hyprland wiki in phase 4; see `docs/audio-bluetooth.md`). Brightness uses `ddcutil` over DDC/CI, not `brightnessctl`: this desktop has no backlight device.
9. `tests/js.sh` runs `tests/fuzzy.test.js` and `tests/calc.test.js` (the launcher's matcher and calculator) and `tests/calendar.test.js` (the calendar's month grid), with node if it's installed, else in Quickshell's own JS engine through `tests/qsjs` (node isn't on the test machine). `tests/bluetooth-agent.sh` tests the pairing agent's protocol on the session bus, touching no Bluetooth state; `tests/polkit-agent.sh` does the same for the polkit agent and never starts PAM. `tests/localsend.sh` runs two LocalSend helpers on ports 53318 and 53319 against each other (files, a folder, decline, a text, cancel), in a temporary folder. `tests/compositor.sh`, `tests/services.sh` and `tests/notifications.sh` check the services against the live system; run them after changing a service. `notifications.sh` needs the notification bus name free, so stop the shell first (`psc stop`, then `psc start`); its `pw-play` is a stand-in, and so is `services.sh`'s `notify-send`, so neither sends a sound or a notification. `services.sh` changes volume, per-app volume (on a silent `pw-cat` stream), Bluetooth power (skipped while a device is connected: powering off dropped the owner's AirPods mid-song, and they don't reconnect by themselves), monitor brightness, Do not disturb's schedule and the night light schedule, checks that settings survive a restart of the test shell, and restores them; it never toggles Ethernet (that would cut the network).

## Gotchas found while building

- An inline `component` used inside the quick settings media card failed with "X is not a type", even with an empty body or declared first in the file; the same code as its own file (`components/MediaButton.qml`) works. It happened again with the calendar's `MonthPage` (now `panels/MonthPage.qml`), while `MonthButton` in the same file works. Cause unknown: if an inline component fails like that, move it to a file.
- Don't give an item a property named like one QtQuick's `Item` already has: `property real left` failed with "Cannot override FINAL property" (`left` is an anchor line), and the whole bar went with it. Hence the toast's `remaining`.
- `FolderListModel` doesn't notice a folder created after it was set up: images put in `~/Pictures/Wallpapers` made later never showed. `Wallpapers` runs `mkdir -p` first and sets the model's folder after.
- Don't name a singleton after a QtQuick type: `State.saved` resolved to QtQuick's `State` and read as undefined (hence `Store`).
- Quickshell modules start tracking on first use: touch them at startup (the test harness does) or the first reads are empty. Mpris too.
- Tray menus are drawn by the shell (`bar/TrayMenu.qml`, `QsMenuOpener`). Don't go back to Qt platform menus (`QsMenuAnchor`, `display()`): they need `//@ pragma UseQApplication` and a restart, look unthemed, and a shell started in that mode hung while exiting. Keep an opener on every open menu level, or the app drops the entries of a submenu opened from it.
- Quickshell has no Bluetooth pairing agent. `services/bluetooth-agent.py` (python-gobject) is the shell's own, run by `Bluetooth.qml`. The system bus lets only root call an agent, so you can't fake BlueZ's questions to the real one: test with `--session` (as `tests/bluetooth-agent.sh` does), or run a copy of `src/` whose agent has that flag to see the launcher's questions.
- Quickshell's `PolkitAgent` starts PAM the moment a request arrives, so cancelling its dialog counted as a failed login for pam_faillock (checked); hence the shell's own agent, `services/polkit-agent.py`, which starts PAM only on submit. Testing with a real prompt (`pkexec /usr/bin/true`) costs a strike per wrong password: never more than one in a row (three lock the account for 10 min, the TTY included), and a correct password clears them. `faillock --user $USER` shows the count.
- `notify-send -i NAME` sends the icon name as the `image-path` hint (app icon empty), and Quickshell turns it into an unchecked `image://icon/NAME` image, which draws a magenta checkerboard when the icon theme lacks it; `Notifs.iconSource` checks such names with `Quickshell.iconPath(name, true)` first.
- Quickshell flags an app's playback stream as `isStream && isSink`, the opposite of what its docs suggest, and a recording app's capture stream as `isStream && !isSink` (checked with `pw-record`); a notification's `expireTimeout` arrives in milliseconds, though the docs say seconds.
- An item declared inside a `ListView` is not put in its `contentItem` (checked: `parent !== contentItem`), so it doesn't scroll with the rows; give it `parent: list.contentItem`. Compare on-screen positions (`mapToItem`) when checking such things: the launcher's selection chip matched its row in content coordinates while drawn `contentY` off.
- `pactl` ignores SIGPIPE, so a long-running one (`pactl subscribe`) outlived a killed shell or test shell (checked; a live reload does stop it). Start such a process through `setpriv --pdeathsig TERM`. WirePlumber won't make an input the default while every jack on it reads "not available": it keeps the configured choice and silently uses another input (`pw-metadata 0` shows both).
- xdg-desktop-portal-hyprland's screencast node is named `xdg-desktop-portal-hyprland` (checked with `pw-dump` during a real Vesktop share); `xdph-streaming-`, a string in its binary, isn't the node name. Check names like this on a live session, not in a binary.
- WirePlumber won't link a test consumer to a GStreamer `pipewiresink mode=provide` video source ("target not found", by name or serial); `tests/services.sh` links its stand-in screencast with `pw-link` instead.
- A layer that holds the keyboard (`WlrKeyboardFocus.Exclusive`) and lets go before dispatching a window focus undoes the switch: Hyprland gives the keyboard back to the window that had it. Dispatch first and keep the keyboard until the layer is gone, as the launcher and the Alt+Tab switcher do (checked).
- A window that appears under a still pointer sends hover-enter to whatever is beneath it: Alt+Tab's cards took the choice from Tab that way. Select on pointer movement, not on enter.
- Hyprland's `focusHistoryID` (`lastIpcObject`) lagged a focus change made while a layer held the keyboard, even after a refresh, so `Compositor` keeps its own focus order from `activewindowv2` events (`recency`).
- To save part of a screen capture (screenshots), put a `ShaderEffectSource` with that `sourceRect` over the `ScreencopyView`, at the same place, and `grabToImage` it with the part's size (checked: a 640x360 crop came out pixel for pixel).
- To show a screen capture in another window (the lock screen's blurred still), `grabToImage` a `ScreencopyView` in a click-through overlay and use the result's `url` as an `Image` source; it stays valid while the `ItemGrabResult` is held (checked: a 1920x1080 grab). Hyprland allows screen capture while locked (grim captured the lock screen), so a still taken after locking would show the lock itself.
- A Bluetooth adapter's `enabled` turns true the moment the shell writes it, while `state` is still `Disabled`; starting discovery then fails ("Resource Not Ready") and isn't retried. Wait for `Bluetooth.ready` (`state` is `Enabled`) before scanning.
- Quickshell's JS engine lacks `Object.fromEntries` (an expired notification rule threw "is not a function" each minute, unnoticed for hours); build the object in a loop. `Array.prototype.flatMap` is missing too; `Object.entries` and `String.fromCodePoint` work.
- `DesktopEntries.heuristicLookup("")` returns some app ("Qt V4L2 video capture utility") rather than nothing: check for an empty app id first (`Apps.nameFor` and `iconFor` do). A window has none for a moment, e.g. right after a switch to an empty workspace.
- `tests/harness` links only `src/services` and `src/Theme.qml`, so a service may `import qs` for `Theme` (Showoff does) but for nothing else; when the harness fails to load, `ipc state` prints nothing and every check fails at once.
- An id hides a property of the same name in its file: with an item `id: menu` and `property var menu`, an unqualified `menu` in a binding read the item, never null, so the desktop's empty menu always showed. Qualify (`root.menu`) or don't reuse the name.
- Don't name an `IpcHandler` function `show`: `qs ipc call desktop show` printed the target's functions instead of calling it (`hide` worked). The desktop icons' are `on` and `off`.
- `Store` writes its file 300 ms after the last change, and a live reload in between drops the change (checked 30 October: desktop positions put back by a test hook, then the hook's removal reloaded the shell, and the test layout came back). After restoring state in a test, wait a second before the next edit, and check `state.json`.
- Only the surface with the keyboard is told which modifiers are down, so the desktop (a background layer) can't see Ctrl on a click unless it takes the keyboard: `Wallpaper.qml` makes it on demand, but only on a workspace without windows, since an on-demand layer may take the keyboard on hover and the desktop shows in the gaps between windows.
- A `MouseArea` inside the item it drags reports the pointer relative to that moving item, so an offset worked out from those coordinates feeds back into the next one and the item jitters (the desktop icons' group drag, 30 October). Measure on a parent that stays put (`mapToItem(root, …)`). A hook that sets the offset directly doesn't catch it.
- The launcher draws a row through the `sourceComponent` table in its delegate, by kind: a new row kind must go there too, or the row is blank while Enter on it still works (the Terminal, `@` and Drives rows, 30 October).
- A singleton starts on first use, so a service that must work in the background from startup (`Drives`, which runs udiskie) goes in `shell.qml`'s `background` list.
- A click in a window didn't close the launcher (owner, 1 November): its `FocusGrab` (Hyprland's focus grab) apparently doesn't clear while the layer holds the keyboard exclusively, though the same grab works for quick settings, which don't. The launcher now covers the screen and closes on a click beside its panel, as the power menu does. A layer that takes the keyboard exclusively and must close on a click outside needs the same.
- A short sound played on a sleeping output can vanish: WirePlumber suspends an idle output after 5 s, and the owner's AudioBox mutes for a moment as it wakes, which swallowed a 40 ms click entirely (heard after 150 ms of silence in front, not without; 1 November). Give short sounds that may start from quiet a 150 ms lead (`tick-wake.wav`, `shutter.wav`). A recording of the output's monitor doesn't show this: the recording itself keeps the output awake.
- Quickshell's JS engine is slow at bulk work: even a bare character loop over 22,000 file names took ~90 ms (measured), and `fuzzy.js`'s `match` ~300 ms. Search through big lists in a helper process (`services/files.py` answers the launcher's `/`) and keep QML to the few results.
- Hyprland drops an empty workspace as you leave it, and a name given with `hl.dsp.workspace.rename` goes with it (checked 3 November); renaming to "" leaves the name empty, not the number. So the shell keeps workspace names itself (`Compositor.names`, in `$XDG_RUNTIME_DIR`, so a reload keeps them and a new login clears them).
- Hyprland's `hl.dsp.window.move({ into_group = dir })` acts on the focused window only (a `window` given with it is ignored, checked 8 November), toward the group in that direction; `hl.dsp.group.toggle({ window })` works by address, and on a grouped window dissolves its group. So tabbed workspaces (`Compositor.setTabbed`) go to the workspace and take its windows in one at a time, a step every 160 ms. In a client's JSON the group's shown window has `visible: true`, but it lags until a refresh. The tabs are Hyprland's own group bar, styled by `Compositor.styleGroups()` through `hyprctl eval 'hl.config(…)'` at startup and on `configreloaded` (owner's call, 9 November: a shell-drawn strip, a layer over every window, covered windows and lagged; runtime settings leave the config file alone).
- The id-hides-a-property trap again (9 November): the mixer's percentage label was `id: value`, so its slider's `onMoved: …(value)` passed the Text item as the volume; WirePlumber saved Cider's and Vesktop's volumes as `nan` (in `~/.local/state/wireplumber/stream-properties`, repaired by hand) and no slider could move them after. `Audio.setStreamVolume` now drops non-finite values.
- A card whose height eases inside quick settings makes the layer resize every frame while the panel opens (laggy): the media card animates only its own part, not Up next's.
- Starting `ddcutil` (Brightness.refresh) holds the shell up about 170 ms: quick settings, which read the brightness as it opened, drew its first frame at 360 ms against the notification centre's 190 (measured with grim, 9 November). It now reads it once the panel has opened. Measure before guessing when something opens slowly: `qs ipc call` then grim every ~25 ms.
- Hyprland pins only floating windows ("Window does not qualify to be pinned"): `Compositor.togglePin` floats a tiled one first.
- A `Variants` over freshly built objects makes its windows again on every change: key it by strings (TabStrips uses the group's first address) and look the object up inside.
- Don't change a service's state from inside a binding that reads it (the launcher's rows started a tldr lookup or Cider search while being worked out): defer it with `Qt.callLater`.
- gpu-screen-recorder reports its frame rate on stderr every few seconds; `Screenshots` logs only lines with "error" or "fail". It stops and finishes the file on SIGINT (`Process.signal(2)`).
- Cider's local API (port 10767) answers `UNAUTHORIZED_APP_TOKEN` without an `apptoken` header; the token in its settings for another app (a phone remote) isn't the shell's to use: the owner makes one and pastes it (Shell settings → Cider token).
- `DesktopEntries` reads the folders in the shell's `XDG_DATA_DIRS`, which comes from the login session: Flatpak, installed at 14:04 on 1 November into a session started at 11:12, had its apps missing from the launcher, since `/etc/profile.d/flatpak.sh` and systemd's `60-flatpak` generator add `/var/lib/flatpak/exports/share` only at login (checked: a test shell found Sober only with that folder added). A new login fixes it; entries added to a folder already listed show up live (checked).
