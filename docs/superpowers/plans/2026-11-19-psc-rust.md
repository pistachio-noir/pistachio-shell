# psc in Rust (Level 1) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace `bin/psc` with a Rust `psc` binary that does everything the script does, plus `status`, `log --errors`, a readable `ipc`, `doctor` and shell completions.

**Architecture:** New crate `rust/psc` (binary `psc`) in the existing workspace. It drives `qs` as the script does and reads `/proc` for status; small modules keep each command testable: `cli.rs` (clap), `shell.rs` (qs calls, pids, stop/start), `status.rs`, `logs.rs`, `ipc.rs`, `doctor.rs`.

**Tech Stack:** Rust 2021, `clap` 4 (derive), `clap_complete` 4, `serde_json` (workspace), `libc` (workspace).

**Spec:** `docs/superpowers/specs/2026-11-19-psc-rust-design.md`

## Global Constraints

- Config name `pistachio`; every `qs` call gets `-c pistachio`. `QS` env var overrides the `qs` program (tests).
- Pass-through must keep arguments byte-identical: `psc <target> <function> args…` → `qs -c pistachio ipc call <target> <function> args…`; `psc ipc|log|list|kill|msg …` and any `-…` first argument → `qs -c pistachio …`, except the new `psc ipc` (no args) and `psc log --errors`.
- Stop: `timeout 3 qs kill`, then per pid wait 5.0 s, SIGTERM, wait 2.0 s, SIGKILL, wait 2.0 s, else error "couldn't stop shell <pid>" (exit 1). Start = `exec qs -c pistachio -n -d`. Force-restart: SIGKILL each direct child (never psc itself) and the shell, wait 5.0 s.
- No new IPC, nothing in `src/` changes on this branch. Owner's shell is live: only read-only commands run against it in tests.
- No staging or commits (owner commits); branch `psc-rust`.

## Review Focus

- `psc launcher toggle` must still work from a Hyprland keybind with no terminal (no TTY, no colour codes) → plain pass-through; Task 1 test `passthrough_without_tty`.
- An IPC target named like a new subcommand (`status`, `doctor`, `completions`, `help`) → the subcommand wins; document it; Task 1 test `subcommand_names_win` (no current IPC target uses those names: check with `qs ipc show`).
- `qs` missing or no shell running → `psc status` says "not running" (exit 1), `psc ipc` explains, no panic; Task 2 test `status_not_running`.
- A shell stuck while exiting → stop escalates TERM then KILL with the waits above; Task 1 integration test with a stand-in `qs` whose fake shell ignores SIGTERM.
- `psc doctor` with a minimal PATH → required items first, exit 1, no panic on missing `fc-list`; Task 3 test.
