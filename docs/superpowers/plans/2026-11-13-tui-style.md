# Classic / TUI Appearance Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement this plan task by task in this checkout. Owner requested a plan approval gate, then phase 1 only. No staging or commits.

**Goal:** Add a persisted, live Classic / TUI Appearance switch while preserving Classic rendering and existing shell functions.

**Architecture:** Keep the existing services, actions and control interfaces. Store owns the style preference, ShellSettings validates it, and shell.qml binds it into Theme; shared components draw either look. Only substantially different layouts get alternate files, selected with loaders so the unused layout is not instantiated. This is the owner's agreed approach; duplicating services or the entire UI would add unnecessary maintenance.

**Tech stack:** Quickshell 0.3.2, Qt Quick/Basic controls, existing Hyprland adapter, existing Python/QtTest fixtures, Helium board renders and grim captures. No new runtime library.

**Spec:** Owner's request of 13 November 2026 and all HTML boards in `pistachio-shell-design/TUI/launcher-and-shell/` (22) and `pistachio-shell-design/TUI/settings/` (24). Read CLAUDE.md and AGENTS.md section 3b before executing.

## Global constraints

- Work on `tui`, descended from `experimental`; never main. Current HEAD at planning: `3969879`; experimental is its ancestor `d338536`.
- Approval required before implementation. Complete and verify one phase before starting the next.
- Classic stays visually unchanged, apart from the required new Appearance selector. Keep original Classic tokens/branches and existing actions.
- System-data services and collection logic stay unchanged. Necessary exceptions are preference persistence/validation and existing compositor frame styling for Settings; phase 2 changes only the callers requesting stats, not its collector.
- Colours, dimensions, font choices and durations live in Theme.qml. TUI uses JetBrains Mono, square neutral borders, title tabs, ruled rows, bracket controls, pistachio for active state only; fades about 80 ms with the existing ease-out curve. Do not retain stagger/slide/scale choreography in TUI.
- TUI bar is always shown at the top, full width, reserving 41 px (40 px contents plus border); its live CPU/memory readings stay enabled all day. Classic retains its existing bottom bar and auto-hide.
- Letter labels such as [W] are decoration only. Preserve existing functional shortcuts; do not implement board-only letter shortcuts. Mock data and desktop sample windows are not shell features.
- Verify every Quickshell type/property used against https://quickshell.org/docs/v0.3.2/ before code; verify Qt controls against Qt docs and CLI/compositor commands on the installed version. Record checked links/properties in the execution notes.
- Check host `pgrep -ax qs` before starting anything. Sandbox pgrep returned empty despite the production shell running; use the host view. Never start a second production shell. Isolated offscreen fixtures are allowed.
- Write QML in place; close Settings before edits; check Configuration Loaded increments and inspect new logs after every edit/reload, including cleanup. Resolve missing HYPRLAND_INSTANCE_SIGNATURE from the live runtime directory before any restart.
- Preserve device state, user content, AI sessions, keyboard/focus behaviour and accessibility. No Hyprland config file edits, paid AI requests or hardware-changing broad suites.
- At every phase boundary and before stopping: update README as applicable, dated decisions/gotchas in CLAUDE.md, checkbox TODO, and CLAUDE-HANDOFF.md. Supply commit text only; owner commits.

## Review focus

1. Rapid switches and restart must preserve the last valid style; invalid stored/input values fall back to Classic. Covered by task 1 persistence tests.
2. Switching with a choice menu/dialog open must not lose an edit, apply a value or leave a keyboard grab. Covered by tasks 2–4 native input checks.
3. Shared controls must preserve non-percent slider units, mirrored direction, disabled/focus state, keyboard/wheel/drag input and existing caller sizing. Covered by task 2 and layout suite.
4. Long real labels, extra current settings pages and 900 × 620 must scroll without clipping controls or menus. Covered by tasks 3–4 bounds tests.
5. Returning to Classic must restore fonts, geometry, compositor rounding and motion, with no stale alternate window. Covered by task 4 captures/geometry and later phase switch checks.
